# التسجيل والدخول بواسطة Google

يعرض نموذج الدخول وإنشاء الحساب زر «المتابعة باستخدام Google». يتفعّل بعد إعداد بيانات تطبيق Web في Google Cloud وإعادة تشغيل API. لا تُطلب كلمة مرور Google داخل المنصة، ولا تُستخدم كلمة مرور Gmail أو كلمة مرور إرسال البريد كـClient Secret.

## إعداد تطبيق محلي

1. أنشئ مشروعًا خاصًا بالمنصة في Google Cloud، ثم جهّز Google Auth Platform باسم المنصة وبريد الدعم والتواصل الذي يختاره مالك المشروع. راجع ووافق بنفسك على سياسة بيانات المستخدم عند طلب Google ذلك.
2. للجهاز المحلي استخدم تطبيقًا من نوع Web application مع عنوان رجوع مطابق تمامًا:
   `http://127.0.0.1:5173/api/auth/google/callback`
3. ابدأ بوضع Testing وأضف حسابات التجربة المطلوبة ضمن Test users. لا تنشر التطبيق للعامة لمجرد اختبار الربط المحلي.
4. نزّل ملف JSON لبيانات Web client إلى مكان خاص خارج مستودع المشروع. لا ترسل محتواه بالمحادثة ولا تضفه إلى Git.
5. من جذر الكود شغّل:

```powershell
node scripts/configure-google.cjs --credentials "C:\private\client_secret_WEB_CLIENT.json"
node scripts/configure-google.cjs --check
```

يحدّث الأمر الأول مفاتيح Google الثلاثة فقط في `backend/.env`، ويحافظ على JWT والبريد والقاعدة وبقية الإعدادات. يتحقق من نوع Web client وصحة القيم ومطابقة عنوان الرجوع، ويرفض استبدال عميل Google مختلف سبق إعداده. لا يطبع Client ID أو Client Secret، ولا يرسل ملف البيانات لأي جهة. أعد تشغيل API بعد حفظ الإعدادات ثم اختبر الزر من عنوان127.0.0.1 نفسه.

الإعداد المنشور يحتاج عنوان HTTPS حقيقيًا وعنوان رجوع مطابقًا، وصفحات الخصوصية وبيانات التطبيق ومتطلبات Google المناسبة للنشر. إعداد localhost لا يغطي النشر تلقائيًا.

لتدوير سر عميل موجود، أعد ضبط/أنشئ سرًا جديدًا لنفس OAuth Web client في Google Cloud، نزّل JSON الخاص به إلى مكان محلي خاص، ثم شغّل `node scripts/configure-google.cjs --rotate-secret "C:\private\client_secret_WEB_CLIENT.json"`. يقبل الأمر نفس Client ID وعنوان الرجوع فقط مع سر جديد، ويحفظه في الخادم دون طباعته. أعد تشغيل API بعد ذلك.

## مسار الحساب

بعد اختيار الحساب في Google، يتحقق Passport على الخادم من الرد ومن state المرتبط بالمتصفح، ثم يُقبل بريد موثّق من Google ومعرّف حساب صالح فقط. ينشأ حساب جديد بصلاحية باحث عن عمل. لا تؤخذ صلاحيات أو نقاط من بيانات Google، ولا تُخزن رموز وصول Google أو رموز التحديث.

يبقى تأكيد البريد برمز المنصة مطلوبًا قبل إنشاء جلسة المنصة، كما في بقية طرق الدخول الحالية. الرمز مرتبط بالمتصفح، والحساب الموقوف مرفوض. الحساب المحلي الموجود بنفس البريد لا يُستبدل مزوده أو كلمة مروره أو دوره. اختلاف معرّف Google المرتبط أو اختلاف البريد لحساب Google المرتبط يرفض الدخول ويحتاج مراجعة مستقلة؛ لا يُغيّر البريد تلقائيًا.

بعد التأكيد يعود المستخدم إلى صفحة محلية آمنة كان يطلبها، أو إلى استكمال بياناته وفق المسار الحالي. لا يمر JWT في عنوان URL. أخطاء الإلغاء أو Google أو إرسال الرمز تعرض رسالة عامة، ولا تعرض ردود المزود أو الأسرار. عند غياب إعداد Google يبقى الزر معطلًا مع إتاحة التسجيل بالبريد.

## الفحوص

`backend/tests/google-oauth.test.cjs` تستخدم قاعدة مؤقتة وتبادل Google وبريدًا وهميين لاختبار state والحساب الجديد وOTP وعدم ربط هوية متعارضة أو حساب موقوف، وتزامن الإنشاء وفشل البريد والوجهة الآمنة. لا تُنشئ الاختبارات حساب Google حقيقيًا.

`backend/tests/google-oauth-client.test.cjs` تختبر روابط البدء ورفض الوجهات الخارجية ورسائل الأخطاء العامة واستيراد JSON محليًا دون كشف الأسرار أو تغيير إعدادات أخرى. نتيجة `--check` تؤكد الإعداد فقط، ولا تدّعي نجاح دخول Google فعلي.

مراجع Google: [تطبيقات خادم الويب وعنوان الرجوع](https://developers.google.com/identity/protocols/oauth2/web-server)، [التحقق من الهوية والبريد](https://developers.google.com/identity/sign-in/web/backend-auth)، [سياسة بيانات المستخدم](https://developers.google.com/terms/api-services-user-data-policy).
