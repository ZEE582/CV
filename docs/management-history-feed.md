# صفحة سجل الإدارة الموحد

الوجهة `/admin/history` متاحة للمدير من القائمة الجانبية ودليل الصفحات. تجمع العمليات المحفوظة للحسابات والشركات في شاشة قراءة واحدة. لا تضيف حدثًا عند البحث أو القراءة، ولا تغيّر الحالات أو الأدوار أو حد الاحتفاظ بالسجل السابق.

## البحث والعرض

- نوع السجل: الحسابات والشركات معًا، أو نوع واحد.
- نوع العملية ضمن العمليات الست المدعومة. تغيير نوع السجل يمسح العملية غير المتوافقة.
- بحث حرفي بالاسم الحالي للحساب أو الشركة، وليس بالبريد أو اسم المنفّذ أو قيم الحقول القديمة.
- أول يوم وآخر يوم مشمولان، **بالتوقيت العالمي UTC**. الأوقات المعروضة في هذه الصفحة بالتوقيت نفسه، بينما نافذة السجل المنفرد السابقة تعرض التوقيت المحلي للمتصفح.
- فلاتر اختيارية لمعرّف المنفّذ ومعرّف الهدف، مع التحقق من اكتمال24خانة قبل القراءة.

تُحفظ الفلاتر والصفحة في الرابط، ويعود تغييرها إلى الصفحة الأولى. يعرض البحث20عملية لكل صفحة. زر «حصر النتائج بهذا السجل» يحدد نوع الهدف ومعرّفه ويمسح بحث الاسم ونوع العملية، ويحافظ على بقية الفلاتر. النتائج القديمة مخفية أثناء القراءة أو تغيير الاستعلام؛ تُلغى القراءات المتجاوزة، ولا توجد إعادة محاولة تلقائية. الخطأ والفراغ والتحديث وإعادة المحاولة حالات منفصلة.

كل عملية تعرض نوع هدفها واسمه ومعرّفه، والمنفّذ ووقتها والحقول المتأثرة والحالة قبل الحفظ وبعده. أسماء الأهداف والمنفّذين حالية، وليست لقطات أسماء تاريخية. الأسماء المفقودة تظهر بعبارة واضحة مع بقاء المعرّف. لا تُعرض قيم النصوص الخاصة أو كلمات المرور أو الرموز.

**العدد هو عدد النتائج المطابقة من الأحداث المحفوظة فقط**. ما زال لكل هدف حد100عملية منذ تفعيل ميزة التسجيل، ولا تعيد هذه الصفحة الأحداث الأقدم المحذوفة أو التغييرات غير المسجلة. انظر [نطاق السجل الأصلي](management-history.md).

## API والصلاحيات

`GET /api/admin/history` يتطلب Bearer لمدير مفعّل، ويرد no-store. الشركة والباحث403، وغير المسجل401. يقبل kind/action/search/actor_id/target_id/from/to/page/limit؛ الحد الافتراضي20والأقصى50، والصفحة من1إلى1000000. يرفض المعرّف غير الصالح والتاريخ غير الحقيقي أو خارج1900..2199 والنطاق المعكوس والتعارض بين نوع الهدف والعملية.

يقرأ MongoDB مصفوفتَي السجل من الحسابات والشركات عبر projection مبكر وunwind وunionWith، ثم facet واحد للأعداد وعناصر الصفحة. لا تُسحب وثائق الحسابات الكاملة إلى الواجهة. تُقرأ أسماء المنفّذين فقط لعناصر الصفحة. الترتيب: وقت العملية تنازليًا، ثم النوع ومعرّف الهدف، ثم النسخة تنازليًا لكسر التعادل بصورة ثابتة.

الرد يتضمن filters/total/page/pages/limit/out_of_range/retained_limit_per_target:100/older_history_available:false/items. الصفحة الخارجة عن النطاق تعود بعناصر فارغة وout_of_range:true؛ الواجهة تصحح الرابط وتقرأ الصفحة الأخيرة الصالحة، بدل عرض فراغ مضلل. كل عنصر يتضمن kind/target_id/target_name/event. يُتحقق في العميل من المعايير المعادة والأعداد والحد والهوية وترتيب النتائج وعدم التكرار ومعايير التاريخ والعملية والمعرّفات، ومن سلامة حدث السجل نفسه.

الرمز في Authorization فقط، دون كوكيز أو تخزين نتائج محلي. تغيير الجلسة أو إلغاء القراءة يمنع اعتماد الرد. لا تُعرض رسائل استثناءات MongoDB أو مزوّد الخدمة الخام.

## حدود الأداء والاتساق

أُضيف maxTimeMS=3000 لمرحلة التجميع وallowDiskUse=false. تجاوز المهلة يعود503برسالة تدعو لتضييق الفلاتر. هذه مهلة تنفيذ تجميع MongoDB، وليست ضمانًا أن كامل طلب HTTP أو انتظار الشبكة وأسماء المنفّذين ينتهي خلال3ثوانٍ. لا توجد مؤشرات جديدة أو نسخة مادية منفصلة للأحداث؛ قد يحتاج حجم إنتاج كبير إلى فهارس وتخزين مخصص يراعي كتابة الحدث ذريًا. الفحص المحلي لا يثبت الأداء على بيانات كبيرة.

ترتيب الصفحات ثابت إذا لم تتغير البيانات. قد تتغير مواقع العمليات بين قراءتين عند وصول عمليات جديدة أو خروج الأقدم من حد100؛ لا يوجد cursor تاريخي ثابت أو snapshot محفوظ أثناء التنقل. التصفية باسم هدف تغير اسمه تعتمد اسمه الحالي. أُضيف [تصدير محلي للصفحة المحمّلة](management-history-export.md) بمعاينة وخيارات خصوصية؛ لا يوجد حذف أو تعديل أو تنبيه أو توسعة لصلاحيات القراءة.

اختبارات الإضافة تستعمل MongoDB مؤقتة وفحص عميل الواجهة، وتغطي العزل والبحث الحرفي والفلاتر المشتركة وUTC والتعادل والصفحات غير الصالحة والحدود والمهلة وعدم إنشاء أحداث أثناء القراءة والجلسات والإلغاء والردود المضللة. معاينة المتصفح ببيانات مصطنعة فقط، دون تجديد جلسة المدير أو تغيير حسابات وشركات التشغيل.
