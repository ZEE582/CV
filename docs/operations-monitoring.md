# فحص الجاهزية وسجلات التشغيل

## الفحص اليدوي

من جذر المشروع، بعد تشغيل API:

```sh
npm run check:health
npm run check:health -- --url http://127.0.0.1:5000
```

الافتراضي `127.0.0.1` ومنفذ `PORT` من بيئة العملية ثم `backend/.env`، أو5000. يقبل `--url` أصل HTTP(S) فقط دون اسم مستخدم أو كلمة مرور أو مسار أو query أو fragment. لا يرسل ملفات تعريف الارتباط أو Authorization، ويرفض إعادة التوجيه. يفحص المسارين بالتوازي، بمهلة ثانيتين لكل طلب وحد4096بايت لردJSON. لا يطبع العنوان المدخل أو الرد الخام أو تفاصيل استثناءات الشبكة.

الخروج0 يعني نجاح فحصي الخادم والقاعدة، والخروج2 يعني فشل فحص واحد أو أكثر، والخروج1 يعني خطأ استخدام أو أداة. الأسباب ثابتة: `alive` و`ready`، أو`database_unavailable` و`connection_failed` و`invalid_response`. لا توجد رسالة بريد أو تعديل بيانات أو إعادة تشغيل تلقائية ضمن الأمر.

## مسارا الخادم

| المسار | المعنى | النتيجة |
|---|---|---|
| `GET /api/live` | قدرة عملية HTTP على الرد |200 و`success:true,status:alive`؛ مستقل عن القاعدة |
| `GET /api/health` | جاهزية القاعدة الفعلية |200 و`success:true,database:connected` بعد ping ناجح، أو503 و`success:false,database:disconnected` |

المساران عامان، قبل تحليل الجسم والجلسة ومحدد الطلبات العام، ولا ينشئان جلسة OAuth. يحملان `Cache-Control: no-store`. مهلة ping ثانية واحدة؛ تجمع الطلبات المتزامنة في ping واحد قيد الانتظار دون الاحتفاظ بنجاح قديم بعد اكتماله. فحص الجاهزية لا يكتفي بحالة اتصال Mongoose؛ يرفض الخطأ والمهلة أو فقدان الاتصال أثناء ping.

لا يكشف الرد URI القاعدة أو اسمها أو حسابها أو مجموعاتها. لا يفحص SMTP أو مزود AI أو Piston أو OAuth أو امتلاء القرص أو صلاحيات كل عملية تجارية؛ نجاحه وحده لا يضمن جميع الوظائف. استعمل `/api/live` لفحص بقاء العملية و`/api/health` لمعرفة قدرتها على استعمال القاعدة، كي لا تؤدي مشكلة القاعدة إلى إعادة تشغيل عمياء مستمرة للعملية.

أضيف healthcheck لخدمة backend في Compose يستعمل Node وping الجاهزية عبر HTTP كل30ثانية، ومهلة3ثوانٍ مع3محاولات وبدء بعد20ثانية. حالة unhealthy لا تعني أن Compose سيعيد تشغيل الحاوية تلقائيًا؛ إدارة التنبيهات والتعافي تحتاج إعدادًا منفصلًا. تعريف Compose موثق لكنه لم يُشغّل بهذه المرحلة؛ تشغيل الموقع الحالي مباشر خارج حاوية backend.

## تتبّع الطلب والسجلات

كل طلب يحصل على UUID جديد من الخادم في الترويسة `X-Request-ID`. يتجاهل الخادم قيمة المتصل لمنع تزوير السجل، وتُتاح الترويسة لأصول CORS المسموح بها. عند الإبلاغ عن عطل، أرفق الرقم والوقت دون كلمة المرور أو الرمز أو ترويسات Authorization/Cookie. يمكن قراءته من تبويب Network في أدوات المتصفح؛ لم تُضف تفاصيل تقنية إلى واجهات المستخدم.

سجلات HTTP في stdout بصيغةJSON، بسطر واحد عند اكتمال الطلب أو انقطاعه. الحقول: الوقت والحدث والمستوى ورقم الطلب والطريقة ومجموعة المسار الثابتة والحالة والنتيجة والمدة بالميلي ثانية. عند انقطاع الرد تُسجل الحالة null والنتيجة aborted؛ لا تُحسب نجاحًا. لا يتكرر السجل عند وصول close بعد finish. فشل كاتب السجل لا يوقف استجابة الموقع، لكنه قد يفقد السجل؛ يلزم مراقبة مساحة السجلات ووجهتها خارجيًا.

المجموعات أسماء ثابتة مثل auth/jobs/applications، والمسارات غير المعروفة تُجمع تحت other_api أوweb. لا تُكتب عناوين URL أو query أو البريد أو محتوى الطلبات والسير أو الرؤوس والكوكيز وIP وUser-Agent ومعرّفات المستخدمين أو الاستثناءات الخام. رموز الفشل المعتمدة فقط: server_error وoauth_email_delivery وoauth_callback؛ محاولة تمرير نص آخر لا تُسجل. أخطاء OAuth التي تنتهي بتحويل302 تُعلّم بالفشل أيضًا دون طباعة رد مزود الخدمة أو الاستثناء.

حُلّ تسجيل البريد في مستمعات أحداث التسجيل والتأكيد وتحديث الملف والاستكمال. تبقى رسائل بدء التشغيل وبعض أحداث الخدمة نصوصًا ثابتة؛ هذه ليست بنية تجميع سجلات شاملة أو سجل تدقيق لتغييرات الموظفين. لا يوجد تتبع للشخص بين الطلبات أو تخزين دائم جديد للسجلات داخل قاعدة البيانات.

## التشغيل والخصوصية

وجّه stdout/stderr إلى وجهة محمية وحدد سياسة دوران واحتفاظ حسب بيئة النشر؛ هذه المرحلة لا تثبت خدمة مراقبة أو ترسل تنبيهات أو تنشئ مهمة مجدولة. لا تمنح مجمّع السجلات صلاحية قراءة `.env` أو `.backups/master.key`. أُضيف استبعاد النسخ المشفرة ومجلدها من سياق Docker أيضًا، بالإضافة إلى Git وZIP.

الاختبارات تستعمل قاعدة مفصولة أو اتصالًا مصطنعًا وخوادم HTTP مؤقتة لاختبار الفشل والمهلة وحجب البيانات ورقم الطلب والانقطاع والردود غير الصالحة. الفحص الشامل يختبر ping فعليًا على MongoDB الاختبارات المؤقتة، ويُجرى الفحص المحلي بعد إعادة تشغيل API. لا يُقطع اتصال قاعدة المنصة الحقيقية لاختبار الأعطال، ولا يُرسل بريد خلال الفحص.
