# النسخ الاحتياطي المحلي لقاعدة المنصة

هذه أداة للمشغّل من الطرفية، وليست صفحة عامة. تنشئ نسخة BSON مضغوطة بأدوات MongoDB الرسمية، ثم تشفّرها بـAES-256-GCM. لا يكتمل الأمر قبل فك النسخة واستعادتها في خادم MongoDB 7 مؤقت منفصل، ومطابقة بصمات المستندات الخام وأعدادها وخيارات المجموعات وفهارسها. تشمل النسخة مرفقات PDF المحفوظة داخل طلبات التوظيف. لا يوجد أمر للاستعادة فوق قاعدة المنصة.

## التحضير مرة واحدة

تحتاج Node ومتطلبات التطوير (`npm ci --ignore-scripts`) وMongoDB 7 ومساحة تكفي النسخة المشفرة والأرشيف المؤقت وقاعدة الاختبار. يجب أن يدعم قرص المشروع hard links (مثل NTFS على Windows) لنشر النسخة المكتملة ذريًا دون استبدال ملف موجود. الحد الحالي للأرشيف المضغوط 512 MiB، ومهلة كل أداة 3 دقائق. لا تدعم هذه النسخة views أو system collections أو إصدارات MongoDB أخرى.

على Windows، من جذر المشروع:

```powershell
./scripts/install-mongodb-tools.ps1
npm run backup:init
```

يثبت السكربت Database Tools **100.20.1** في `.cache` فقط ويتحقق من SHA-256 للأرشيف الرسمي قبل التشغيل. على Linux/macOS ثبّت الإصدار نفسه من [MongoDB](https://www.mongodb.com/try/download/database-tools) في PATH أو عيّن `MONGODB_TOOLS_DIR` إلى مجلد الأدوات الموثوق. لا ينزّل أمر النسخ أدوات Database Tools تلقائيًا. قد ينزّل مشغل الاختبار MongoDB 7.0.24 إلى `.cache/mongodb` عند أول تحقق.

يحفظ `backup:init` مفتاحًا عشوائيًا بطول 32 بايت في `.backups/master.key`، ويرفض استبداله إن كان موجودًا. لا تعرض محتواه أو ترسله بالمحادثة. احتفظ بنسخة منفصلة محمية من المفتاح، وانقل النسخ المشفرة إلى وسيط مستقل: وجود المفتاح والنسخ على الجهاز نفسه لا يحمي من فقدان الجهاز. فقدان المفتاح يجعل النسخ غير قابلة للاسترجاع. الأداة لا تنشئ نسخة خارج الجهاز ولا جدولًا تلقائيًا.

## إنشاء نسخة والتحقق منها

أوقف الكتابات إلى قاعدة التطبيق أولًا، بما فيها API وأي مستورد أو مهمة مجدولة؛ اترك MongoDB يعمل. اضبط `MONGO_URI` في `backend/.env` على قاعدة التطبيق المطلوبة باسم صريح، ثم:

```sh
npm run backup:create
npm run backup:verify -- ".backups/backup-<timestamp>-<random>.ttbackup"
```

أعد تشغيل API بعد اكتمال النسخ أو فشله. الأداة نفسها لا توقف خدماتك. `MONGO_URI` في البيئة يتقدم على الملف. لا تمرر عنوان الاتصال كوسيط سطر أوامر. تقارن الأداة المصدر قبل التفريغ وبعده وترفض التغييرات المرصودة، ثم تقارن الاستعادة بالمصدر المقروء؛ هذه الفحوص لا توفر لقطة زمنية ذرية لقاعدة standalone إذا استمرت كتابات متزامنة. لا تستعمل الأداة `--oplog` ولا تدعي ضمان نقطة زمنية أثناء الكتابة.

أمر الإنشاء يطبع مسار النسخة وحجمها وSHA-256 وأعداد السجلات فقط. النسخ الناجحة بأسماء فريدة لا تُستبدل. يتحقق أمر الفحص من مصادقة التشفير كاملة قبل تشغيل الاستعادة. عنوان خادم الاستعادة يُنشأ داخليًا على loopback ومنفذ عشوائي؛ لا يُقبل عنوان استعادة من الملف أو المشغّل. تُوقف قاعدة الاختبار وتُحذف ملفات العمل المؤقتة في `finally`، ولا تُستدعى عمليات حذف على قاعدة المصدر. الخطأ أو الانقطاع القسري قد يترك مجلد `.tmp-*` خاصًا؛ راجعه محليًا بعد التأكد أن العملية انتهت. لا يوجد ادعاء مسح آمن للقرص.

## الخصوصية وحدود الاستعادة

تُقيّد صلاحيات `.backups` للمستخدم الحالي (Windows ACL، أو 0700/0600 على Unix). توجد بيانات غير مشفرة أثناء التفريغ والاستعادة داخل المجلد المؤقت المحمي؛ تشفير القرص وصلاحيات الجهاز جزء من حماية التشغيل. لا تمنع هذه الأداة مدير الجهاز أو برمجية تعمل بحسابك من القراءة. ملفات `.env` وإعدادات SMTP وJWT ليست جزءًا من نسخة قاعدة البيانات؛ احفظ إعدادات التشغيل بطريقة منفصلة آمنة.

`.backups` و`*.ttbackup` مستبعدان من Git، وفحص بنية المشروع يرفض تتبعهما. لا تُضمّن النسخ أو المفتاح في ZIP الكود. لا تشارك المفتاح مع النسخة. لا تقبل نسخًا من جهات غير موثوقة؛ تحقق GCM يثبت تطابق الملف مع المفتاح ولا يثبت سلامة بياناته التجارية أو خلو المرفقات من محتوى ضار.

الاستعادة الفعلية بعد حادث تحتاج مشغّلًا وخطة نقل معتمدة: تحقق من نسخة مستقلة أولًا، جهّز قاعدة جديدة وصلاحياتها، راجع البيانات، ثم غيّر عنوان التطبيق. هذه المرحلة لا تضيف استعادة إنتاج أو تبديلًا تلقائيًا أو نسخًا سحابية أو سياسة حذف/احتفاظ. [وثائق mongodump](https://www.mongodb.com/docs/database-tools/mongodump/) و[وثائق mongorestore](https://www.mongodb.com/docs/database-tools/mongorestore/) تشرح توافق الإصدارات والقيود.

## الاختبارات

```sh
npm test
npm run test:backup
```

اختبارات الوحدة ضمن الفحص المعتاد: رفض قواعد النظام، التشفير وفكّه، المفتاح الخطأ، العبث بالمحتوى والترويسة، الملف المبتور، عدم استبدال الملفات وحدود تنظيف المسارات. اختبار `test:backup` منفصل ويتطلب Database Tools: ينشئ قاعدة مصطنعة تتضمن PDF وBSON طويلًا وتواريخ ومجموعة فارغة وفهرسًا مركبًا فريدًا وفهرس TTL وقاعدة تحقق، ثم يختبر النسخ والاستعادة ومطابقة الأصل دون الكتابة إليه.
