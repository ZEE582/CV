# تطوّر — TTWar

واجهة React واحدة وAPI واحدة بـExpress وMongoDB. جُمعت صفحات المصادقة والملف الشخصي، والواجهة العامة والشركات والدعم، والوظائف وCV ولوحة الإدارة في مشروع يعمل على Windows وLinux دون اختلاف أسماء المجلدات بحالة الأحرف.

شريط تنقل موحد للأقسام الرئيسية، وتبقى الخيارات الثانوية داخل صفحات الحساب والإدارة والتدريب. يبدأ الزائر بالصفحة الرئيسية، ويتطلب استخدام باقي صفحات المنصة حسابًا مسجلًا وجلسة دخول. تبقى صفحات الدخول وإنشاء الحساب والتأكيد واستعادة كلمة المرور متاحة للزائر. راجع [طريقة الاستخدام والصيانة](docs/unified-navigation.md).

## التشغيل المحلي

تحتاج Node.js 22.12 أو أحدث وnpm 11.21.2 وMongoDB محلية أو رابط قاعدة بيانات خاصًا بك. الأوامر التالية تستعمل نسخة npm المحددة دون تغيير نسختك العامة:

```bash
npx --yes npm@11.21.2 ci --ignore-scripts
npx --yes npm@11.21.2 run setup
```

الأمر الثاني ينشئ `backend/.env` و`frontend/.env` دون الكتابة فوق إعدادات موجودة، ويولّد سر JWT عشوائيًا. اضبط `MONGO_URI` و`EMAIL_USER` و`EMAIL_PASS` في `backend/.env` ثم شغّل:

```bash
npx --yes npm@11.21.2 run dev
```

- الموقع: `http://127.0.0.1:5173`.
- API: المنفذ `5000`، والفحص الصحي `/api/health`، والتوثيق `/api/docs`.
- جميع طلبات الواجهة تمر عبر `/api` وVite proxy. عند استخدام منفذ API مختلف حدّث proxy في `frontend/vite.config.ts` أيضًا.
- Google وGitHub وLinkedIn والمساعد الذكي وتنفيذ الكود خدمات اختيارية. أمثلة متغيراتها في ملف البيئة. غيابها لا يمنع بدء API؛ تعيد مساراتها رسالة عدم توفر واضحة. OAuth يحتاج بيانات تطبيقك وعنوان callback مطابقًا وعنوان `CLIENT_URL` الخاص بالواجهة.

للتسجيل بواسطة Google، راجع [دليل ربط Google](docs/google-signin.md). بعد تنزيل بيانات Web client إلى مكان خاص خارج المستودع، يستوردها `node scripts/configure-google.cjs --credentials "PATH_TO_JSON"` إلى إعدادات الخادم فقط دون طباعة الأسرار. استخدم `node scripts/configure-google.cjs --check` لفحص جاهزية الإعداد.
- البريد مطلوب للتسجيل والدخول. `EMAIL_USER` حساب الإرسال، و`EMAIL_PASS` كلمة مرور تطبيق Gmail مناسبة لهذا الحساب؛ لا تستخدم كلمة مرورك الأساسية. لا يوجد تجاوز مصادقة أو كود دخول مطبوع في النسخة المسلّمة.
- في الإنتاج استخدم HTTPS و`NODE_ENV=production` و`CLIENT_URL` المطابق لنطاق الموقع. عند النشر خلف proxy موثوق اضبط Express وفق بيئة النشر؛ لا تثق بترويسات proxy غير موثوقة تلقائيًا.

لإضافة دليل الشركات دون مسح بيانات موجودة في قاعدة التطوير:

```bash
npm run seed -w backend
```

لإنشاء مدير، اضبط `ADMIN_EMAIL` وكلمة مرور جديدة بطول 12 حرفًا على الأقل في `ADMIN_PASSWORD`، ثم:

```bash
npm run create-admin -w backend
```

الأمر لا يغيّر دور حساب موجود ولا يطبع كلمة المرور. الدخول الإداري يستخدم كلمة المرور ثم كود البريد مثل بقية الحسابات. استيراد مسائل البرمجة من بيانات المستودع متاح بواسطة `node backend/seeder/importData.js` بعد ضبط بيئة قاعدة التطوير.

## إعداد البريد وفحصه

للإرسال عبر Gmail، ضع في `backend/.env` المحلي عنوان الإرسال في `EMAIL_USER` وكلمة مرور التطبيق في `EMAIL_PASS`. لا تستخدم كلمة مرور الحساب العادية أو تحفظ هذه القيم في Git. إنشاء كلمة مرور التطبيق يتطلب التحقق بخطوتين، وقد لا يتاح لبعض الحسابات المُدارة أو المحمية؛ راجع [تعليمات Google](https://support.google.com/accounts/answer/185833?hl=ar). إذا لم يتوفر الخيار، يلزم اختيار آلية إرسال أخرى بدل تعطيل حماية الحساب. تسجيل دخول المستخدمين بواسطة Google OAuth منفصل عن صلاحية إرسال البريد.

ترك `SMTP_HOST` و`SMTP_PORT` و`SMTP_SECURE` فارغة يحافظ على Gmail عبر `smtp.gmail.com:465` باتصال TLS. لبريد نطاق آخر، ضع اسم خادم SMTP دون URL في `SMTP_HOST` والمنفذ في `SMTP_PORT` و`true` أو `false` في `SMTP_SECURE`. المنفذ 465 يستخدم `true`، والمنفذ 587 يستخدم `false` مع STARTTLS إجباري. إذا لم تحدد المنفذ، يستخدم الخادم المخصص 587، أو465 عند اختيار `true`. تظل شهادة الخادم متحققًا منها ولا يوجد خيار بيئة لتعطيل التشفير أو فحصها. يمكن ضبط `EMAIL_FROM` كعنوان مرسل واحد معتمد عند اختلافه عن اسم مستخدم SMTP؛ إن تُرك فارغًا يستخدم عنوان `EMAIL_USER`.

```sh
npx --yes npm@11.21.2 run check:email
npx --yes npm@11.21.2 run check:email -- --connect
```

الأمر الأول يفحص الإعدادات محليًا دون اتصال، ولا يعد نجاحه إثباتًا لوصول البريد. الأمر الثاني يتصل بالخادم ويختبر التشفير والمصادقة دون إرسال رسالة؛ يُستخدم بعد إضافة إعدادات حساب الإرسال. لا يعرض الفحص كلمة المرور أو عنوان الحساب أو رد الخادم الخام. خروج 0 يعني نجاح نوع الفحص المطلوب، و2 يعني أن الإعداد ناقص أو الاتصال لم ينجح، و1 يعني استخدامًا غير صالح أو فشل الأداة. `configured` تعني أن الإعداد صالح شكليًا فقط؛ `verified` يتطلب فحص الاتصال.

حتى فحص الاتصال الناجح لا يثبت قبول عنوان المرسل أو وصول الرسائل إلى البريد الوارد؛ [Nodemailer يوضح حدود verify](https://nodemailer.com/smtp#verifying-the-configuration). اختبر بعدها التسجيل والدخول والاستعادة بعنوان مستلم مصرح به، وراجع البريد غير المرغوب فيه. أعد تشغيل API بعد تغيير البيئة. لا توجد رسالة اختبار تلقائية ولا تجاوز لرموز التحقق أو تسجيل لها في السجلات.

تحتوي رسائل الرموز على HTML ونص عادي. تعاد محاولة الأخطاء المؤقتة المعروفة فقط، بحد ثلاث محاولات وفاصل ثانيتين؛ لا تعاد أخطاء المصادقة أو الرفض الدائم أو فشل TLS أو الأخطاء غير المصنفة. السجلات تعرض تصنيفًا ثابتًا دون رسالة مزود البريد الخام. تبقى محاولة الاستعادة في ذاكرة عملية الخادم بعد رد الاستلام؛ لا توجد قائمة بريد دائمة، وقد يلزم طلب رمز جديد بعد انقطاع الخادم.

## سجل تغييرات الحسابات والشركات

داخل سجل الإدارة، يتيح «تصدير الصفحة المحمّلة» مراجعة النسخة ثم تنزيل CSV أو JSON من العمليات الظاهرة فقط. الأسماء والمعرّفات مستبعدة افتراضيًا مع خيارات إدراج مستقلة، ولا توجد قراءة إضافية للقاعدة أو مشاركة تلقائية. [دليل تصدير صفحة السجل](docs/management-history-export.md).

يمكن للمدير فتح `/admin/history` من القائمة الجانبية للبحث في العمليات المحفوظة للحسابات والشركات معًا، حسب النوع والعملية والاسم الحالي والتاريخ ومعرّفات الهدف والمنفّذ، مع صفحات وفلاتر محفوظة بالرابط. الأوقات والفلاتر هناك UTC، والعدد يشمل المحفوظ فقط ضمن آخر100عملية لكل هدف. [دليل صفحة السجل الموحد](docs/management-history-feed.md).

للإدارة زر «سجل التغييرات» في بطاقات الحسابات والشركات، يعرض المنفّذ والوقت والحقول المتأثرة والحالة قبل الحفظ وبعده. تُكتب العملية مع التعديل ذريًا، ويُحتفظ بآخر100عملية لكل سجل منذ تفعيل الميزة، دون تعبئة تاريخية أو حفظ قيم النصوص الخاصة وكلمات المرور. العرض للمدير فقط. العمليات المشمولة والحدود في [دليل سجل التغييرات](docs/management-history.md).

## فحص الجاهزية وسجلات التشغيل

شغّل `npm run check:health` لفحص عملية HTTP واتصال MongoDB، أو أضف `-- --url http://127.0.0.1:5000` لعنوان API آخر. `/api/live` يفحص بقاء العملية؛ `/api/health` يعيد503 عند غياب القاعدة أو فشل ping، و200 عند نجاحه. كل طلب يحمل `X-Request-ID` مولدًا من الخادم، وسجلات HTTP تستبعد URL والبيانات الشخصية والرموز. تعريف Compose يتضمن healthcheck للـbackend؛ لا توجد خدمة تنبيهات أو إعادة تشغيل تلقائية جديدة. التفاصيل والقيود في [دليل فحص التشغيل](docs/operations-monitoring.md).

## البناء والتحقق

```bash
npx --yes npm@11.21.2 run check
```

يشغّل TypeScript وESLint وفحص البنية والاختبارات والبناء. اختبارات API تستخدم MongoDB مؤقتة ومزود بريد وهميًا داخل الاختبارات فقط، ولا تقرأ ملف البيئة ولا تتصل بقاعدة بياناتك. أول تشغيل للاختبارات قد ينزّل ملف تشغيل MongoDB ويخزّنه في `.cache/mongodb`. تنهي الاختبارات قاعدة البيانات المؤقتة بعدها.

```bash
npm run build
npm start
```

بعد البناء، يقدّم Express ملفات الموقع وAPI من المنفذ نفسه، ويدعم فتح روابط الصفحات مباشرةً. التشغيل الفعلي يحتاج قاعدة البيانات وإعدادات البيئة المذكورة.

لتشغيل Docker Compose من الجذر، عيّن `MONGO_USER` و`MONGO_PASS` و`MONGO_DB` و`JWT_SECRET` و`CLIENT_URL` وبقية الإعدادات اللازمة في `backend/.env`، ثم:

```bash
docker compose --env-file backend/.env -f backend/docker-compose.yml up --build
```

استخدم قيم مستخدم وكلمة مرور Mongo مناسبة لرابط URI، مع ترميز المحارف الخاصة عند الحاجة. Compose يحفظ بيانات Mongo في volume، ولا يفتح منفذ قاعدة البيانات خارج شبكة الحاويات. إعداد حاويات Mongo وAPI لم يُشغّل على جهاز الفحص؛ تعمل هاتان الخدمتان مباشرةً، ويستخدم Docker Engine داخل Ubuntu WSL لخدمة تنفيذ الأكواد المنفصلة فقط.

### اختبار دورة التوظيف المترابطة

```sh
npx --yes npm@11.21.2 run test:journey
```

يشغّل ثلاث رحلات API على MongoDB مؤقتة باسم `ttwar_recruitment_journey`، ويمنع الاتصال بمنفذ قاعدة التطوير27171. لا يقرأ ملف البيئة المحلي ولا يرسل بريدًا خارجيًا. يُنشأ المدير الأول في قاعدة الاختبار فقط، ثم تحصل حسابات المدير والشركتين والباحثين على رموزها من الدخول أو التسجيل وتأكيد الرمز الحقيقي الذي ولّده التطبيق؛ تُلتقط رسائل الاختبار محليًا ولا تُصنع رموز JWT مباشرة.

يغطي الاختبار تسجيل الباحث وحفظ الملف والسيرة، وإنشاء شركتين وحسابيهما عبر المدير، ونشر وظيفة موقوفة ثم فتحها، والبحث والتقديم ومنع التكرار ومراجعة الشركة والمدير، والإعلان المحفوظ والسجل وتصدير HTML باستخدام مولّد الواجهة مع استجابة API الفعلية، والرسائل والسحب المسموح. يفحص كذلك عزل الوظائف والطلبات والرسائل بين الشركتين وخصوصية نسخة الطلب والسيرة، وإبطال الجلسات بعد إيقاف الحساب وإعادته، والاحتفاظ بطلبات الباحث عند إيقاف الشركة.

هذه اختبارات API ومولّد التصدير، وليست اختبار نقرات متصفح أو وصول بريد Gmail فعلي. تُزال قاعدة الاختبار عند انتهائها؛ لا تستخدم حسابات أو وظائف التشغيل ولا تغيّر حالاتها.

## تنظيم المصدر

```text
frontend/src/
  App.tsx                 # تعريف المسارات المشتركة
  shared/                 # API والجلسة وحماية الصفحات
  features/
    auth/                 # دخول، تسجيل، تحقق، أسئلة، ملف شخصي
    public/               # الرئيسية، الشركات، الدعم
    platform/             # وظائف، CV، مساعد، إدارة
backend/
  app.js                  # تركيب API دون تشغيل خادم تلقائيًا
  server.js               # اتصال Mongo وتشغيل الخادم
  modules/auth/           # المصادقة والبريد وOAuth والملف الشخصي
  models/                 # مصدر المستخدم والشركات والوظائف الموحد
  routes/                 # مسارات الوظائف والشركات وCV والإدارة وغيرها
  tests/                  # اختبارات تكامل فعلية على Mongo مؤقتة
```

`package-lock.json` الوحيد في الجذر. لا تنشئ أقفالًا فرعية ولا ترفع `node_modules` أو `.env`.

### توافق التبعيات

ينفذ `check:deps` فحص شجرة الحزم المثبتة قبل بقية الفحوص، ويرفض الحزم المفقودة أو المتعارضة. ينفذ `audit:deps` فحص التحذيرات الأمنية عبر الشبكة. شغّلهما باستخدام `npx --yes npm@11.21.2 run check:deps` و`npx --yes npm@11.21.2 run audit:deps`. بقية أوامر npm أدناه تفترض تثبيت نسخة متوافقة؛ يمكنك إضافة البادئة نفسها إليها.

تفرض `.npmrc` نسخة npm مدعومة لمنع إعادة إنشاء شجرة خاطئة. نسخة npm 11.13 تعاني مشكلة مع تجاوزات الحزم داخل workspaces؛ اختُبرت 11.21.2 هنا. راجع [المشكلة الرسمية](https://github.com/npm/cli/issues/9514).

تجاوزات `glob` و`minimatch` محصورة بمستخدميها المباشرين في Swagger وTypeScript ESLint؛ تشمل تغييرات رئيسية واختُبرت مطابقة ملفات المسارات وخدمة مشاريع TypeScript. راجع التجاوزات عند تحديث الحزم الأم وأزلها عندما تعتمد الإصدارات المصححة رسميًا. رُفعت `react-pro-sidebar` إلى 1.1.0 لدعم React 18 وإزالة تعارض النسخة القديمة، مع الحفاظ على صلاحيات روابط الإدارة وسياق الشركة.

## الحسابات القديمة والأسرار

النسخ السابقة رفعت أسرارًا وبيانات اتصال داخل Git. أُزيلت من المصدر الحالي، لكن يجب إلغاء أو تدوير مفتاح AI وسر JWT وكلمة مرور Mongo وكلمات مرور الإدارة التي كُشفت من لوحات الخدمات نفسها. حذف الملف الحالي لا يلغي القيم ولا يمحو تاريخ Git. لم يُعاد كتابة تاريخ الفروع المشتركة؛ نسّق تنظيفه مع الفريق إذا احتجتم ذلك بعد تدوير الأسرار.

نموذج المستخدم الموحد يقرأ حقول `password` القديمة ويدعم تسجيل الدخول بواسطة `password_hash` القديم؛ يُحوّل الحساب إلى حقل `password` عند تغيير كلمة المرور. حسابات الدور القديم `user` تُعامل كـ`seeker`. لا تُغيّر قاعدة الإنتاج قبل أخذ نسخة احتياطية وفحص عينات من حساباتها؛ الاختبارات أجريت على بيانات مؤقتة، لا على قاعدة المشروع الحقيقية.

## الصفحات

`/home`، `/companies`، `/support`، `/jobs`، `/company/:id`، `/applications`، `/cv`، `/ai`، `/login`، `/forgot-password`، `/reset-password`، `/signup`، `/verify-email`، `/questions`، `/profile`، `/pages`.

الإدارة تحت `/admin/*` وتحتاج دورًا مناسبًا. الشركات والتقويم والفريق وجهات الاتصال وإحصاءات الإدارة مرتبطة بالـAPI. الفواتير والنموذج الإداري غير متاحين حاليًا. منح النقاط من المتصفح معطل حتى إضافة نظام إنجازات موثوق في الخادم. تنفيذ الكود يحتاج خدمة Piston متوافقة تحددها أنت في `CODE_EXECUTOR_URL`، ولا ينفذ كود المستخدم داخل عملية API.

### دورة التوظيف

1. من `/admin/companies` يستطيع المدير إضافة الشركة وإنشاء حساب مسؤولها باستخدام «إنشاء حساب الشركة». الدخول العادي يحتاج البريد للتحقق. احتفظ ببيانات الحساب وشاركها مع المسؤول بطريقة آمنة.
2. من `/admin/company-dashboard` يستطيع مسؤول الشركة نشر الوظيفة وتعديلها وإيقافها أو تفعيلها. يستطيع المدير اختيار شركة لإدارة وظائفها.
3. يفتح الباحث الوظيفة من `/jobs` ويقدّم من تفاصيلها. رسالة التقديم والسيرة اختياريتان. يمكن إرفاق ملف PDF حتى5MiB أو رابط HTTP/HTTPS، أو التقديم دونهما. لا يُرسل ملف ورابط معًا.
4. تعرض `/applications` طلبات الباحث وحالاتها، وتتيح سحب الطلب في حالة الانتظار فقط.
5. تعرض `/admin/applicants` الطلبات بحسب الشركة والوظيفة، وتتيح للمالك أو المدير تحديث الحالة. قائمة الوظائف الإدارية `/api/jobs/manage?company_id=...` تتطلب صلاحية الشركة المالكة أو المدير وتشمل الوظائف الموقوفة.

النقر على بطاقة الوظيفة يحافظ على معرفها في `?job=...` عند الانتقال إلى الشركة. يحتفظ مسار الدخول بوجهة داخل الموقع للباحث بعد التحقق واستكمال البيانات. اختبارات API تغطي دورة التوظيف وعزل بيانات الشركات ومنع نقل ملكية الوظيفة بعملية التعديل والربط المتزامن لحساب الشركة. ليست هذه شهادة باكتمال جميع الميزات أو اختبار كل مزود خارجي.

### إرفاق ملف السيرة أثناء التقديم

يقبل `POST /api/applications` الطلب القديم بصيغةJSON، أو `multipart/form-data` بحقول `job_id` و`cover_letter` وملف `cv_file` واحد. لا تُرفع الملفات منفصلة عن الطلب: يُحفظ PDF في حقل ثنائي مخفي عن الاستعلامات العادية داخل وثيقة الطلب نفسها، مع اسم وحجم للعرض. فشل التقديم أو تكراره لا يترك ملفًا مخزنًا بلا طلب، وسحب الطلب يحذف مرفقه معه.

يسبق التحقق من الحساب ودور الباحث قراءة الملف. الحد5MiB وملف واحد، مع حدود لحقول multipart، وعشر محاولات رفع لكل حساب خلال15 دقيقة، وأربعة طلبات رفع متزامنة لكل عملية API. يُرفض الامتداد أو MIME غيرPDF والمحتوى الذي لا يبدأ بترويسةPDF أو لا ينتهي بعلامةEOF. هذا فحص صيغة محدود، وليس تحليلPDF شاملًا أو فحصًا ضد البرمجيات الضارة. لا يقبل الخادم بيانات المرفق الداخلية من JSON.

المسار `GET /api/applications/:id/cv` يحتاج رمز جلسة في الترويسة، ويسمح لصاحب الطلب أو المالك الحالي للشركة المعنية أو المدير فقط. يعيد ملفًا كتنزيل مع `private, no-store` و`nosniff` وسياسةsandbox؛ لا يوجد رابط عام أو رمز دخول في URL. تغيير ربط الشركة يغيّر حق صاحبها في القراءة. يظل الملف متاحًا لصاحبه بعد حذف الإعلان؛ لا تتاح للشركة التي لا تملك سجل الشركة صلاحية تنزيله.

زر التنزيل في تقديماتي والمتقدمين يتحقق من الجلسة ونوع الرد وحجمه قبل طلب حفظه. الملف المختار ورسالة التقديم يبقيان عند تعذر تأكيد الإرسال، ويلزم التحقق من حالة الطلب قبل تكراره. ملفاتWord غير مدعومة للرفع في هذه المرحلة؛ يمكن تصدير السيرة إلىPDF أولًا. الملف الأصلي لا يدخل نسخة مراجعة الطلبHTML/PDF؛ يُدرج اسمه وحجمه فقط عند اختيار بيانات السيرة المرفقة، وهي مستبعدة افتراضيًا.

نسخ MongoDB الاحتياطية تحتوي المرفقات أيضًا، وتحتاج سياسة وصول واحتفاظ مناسبة. هذا التخزين مناسب للحد المحدد هنا، ولا يوفر تشفيرًا مستقلًا لكل ملف أو فحص فيروسات أو خدمة تخزين ملفات خارجية.

### متابعة طلبات الباحث عن عمل

تعرض `/applications` طلبات الحساب الحالي مع البحث باسم الوظيفة أو الشركة، والتصفية بالحالة مع أعدادها، والترتيب والتقسيم إلى صفحات من 8 طلبات. تُحفظ الفلاتر في الرابط؛ البحث والصفحات يجريان محليًا بعد تحميل قائمة الحساب كاملة، ولا يعتمدان على صفحات الخادم.

تظهر الوظائف الموقوفة أو المحذوفة بوضوح، ويمكن مراجعة رسالة التقديم ورابط السيرة المرفق. سحب الطلب قيد الانتظار يحتاج مراجعة اسم الوظيفة والتأكيد، ويرسل `expected_version` إلى مسار السحب. لا تُعرض رسالة نجاح إلا إذا أكد الخادم معرف الطلب نفسه، ويُطلب تحديث القائمة عند التعارض أو انقطاع تأكيد السحب. تغيير الجلسة يمنع الطلبات المعلقة من عرض بيانات الحساب السابق. لا تُجرى قرارات توظيف أو تغييرات حالات تلقائية.

من «تفاصيل الوظيفة» في `/applications` يستطيع صاحب الطلب التبديل بين الإعلان المحفوظ مع طلبه والإعلان الحالي. ينشئ الخادم النسخة للطلبات الجديدة من قراءة الوظيفة والشركة أثناء معالجة التقديم، ويحفظ معها تاريخ الالتقاط ونسخة الوظيفة عند توفرها. لا يضمن ذلك مطابقة إعلان كان المتصفح قد عرضه قبل إرسال الطلب، ولا توجد معاملة موحدة بين قراءة الشركة والوظيفة وحفظ الطلب.

المسار الخاص `GET /api/applications/:id/job` مخصص للباحث مالك الطلب، ويعيد `snapshot` للنسخة المحفوظة و`job` للتفاصيل الحالية. تبقى النسخة بعد تعديل الوظيفة أو حذفها أو حذف الشركة، بينما تعود التفاصيل الحالية غير متاحة عند حذف الوظيفة أو انتقالها إلى شركة أخرى. لا تتوفر نسخ محفوظة للطلبات القديمة ولا تُنشأ لها نسخ بأثر رجعي. لا تغيّر القراءة حالة الطلب أو عداد مشاهدة الوظيفة، ويبقى الوصول العام للوظائف الموقوفة محظورًا.

تحتوي النسخة حقول الإعلان العامة فقط، ويُحجب الراتب إذا لم يكن معلنًا أثناء الالتقاط. الراتب الذي كان معلنًا عند التقديم يبقى ضمن النسخة التاريخية حتى إذا أُخفي من الإعلان الحالي لاحقًا. لا يقبل API نسخة من العميل، وتُحظر تعديلات النسخة عبر عمليات التحديث المستخدمة في التطبيق. ليست النسخة سجلًا موقّعًا أو حماية من مدير قاعدة بيانات يكتب مباشرةً. لا تُرسل النسخة الكاملة في قوائم المتقدمين أو قائمة طلباتي؛ ترسل الأخيرة العنوان واسم الشركة وعلامة توفرها فقط. سحب الطلب يحذف معه النسخة المحفوظة.

تُفتح التفاصيل داخل نافذة يمكن إغلاقها دون فقدان الفلاتر. رابط الوظيفة العامة يظهر للوظيفة النشطة، ويحتفظ بسياق العودة إلى طلباتي وفلاترها مع رفض الوجهات الخارجية. لا توجد إعادة تقديم أو تغيير حالة تلقائي من نافذة التفاصيل.

### سجل حالة طلب التوظيف

زر «سجل حالة الطلب» في تقديماتي يعرض الحالة التي قرأها للتو وآخر 100 حدث، بتوقيت الخادم المعروض حسب Asia/Hebron. يُسجّل إرسال الطلب الجديد، وتُضاف التغييرات الفعلية للحالة مع تحديث الحالة والنسخة ذريًا في وثيقة الطلب نفسها. لا يضيف حفظ الحالة نفسها حدثًا مكررًا، لكنه يحافظ على زيادة نسخة الطلب لتوافق عقد API السابق. يُرفض الإصدار القديم أو المستقبلي قبل الحفظ.

المسار `GET /api/applications/:id/history` خاص بالباحث مالك الطلب، ويعمل حتى بعد حذف الوظيفة أو الشركة. يُعرض دور من نفّذ التغيير فقط، دون أسماء الموظفين أو معرفاتهم. حقول السجل الداخلية مستبعدة من قوائم الطلبات والمتقدمين، ولا يقبل العميل كتابة السجل. الطلبات القديمة لا تحصل على تاريخ مختلق؛ يبدأ سجلها عند أول تغيير فعلي بعد التحديث. يوضح الرد `complete` و`total_events` و`truncated`، وتُحفظ آخر 100 واقعة فقط مع العدد الإجمالي، وتُحذف مع سحب الطلب. ليس السجل موقّعًا أو محميًا من الكتابة المباشرة من مدير قاعدة البيانات.

عند إغلاق سجل أحدث من القائمة، تعاد قراءة الطلبات مع بقاء فلاترها. السجل لا يرسل إشعارات فورية ولا يحدّث حالات تلقائيًا.

### نسخة شخصية من طلب التوظيف

زر «نسخة من الطلب» في تقديماتي يفتح معاينة قابلة للطباعة أو التنزيل كملف HTML مستقل. يمكن اختيار رسالة التقديم ورابط السيرة والإعلان المحفوظ وسجل الحالات؛ رابط السيرة مستبعد افتراضيًا، والأقسام غير المحددة لا تدخل محتوى الملف. تُعرض الروابط كنص فقط دون جلب السيرة أو الصور أو الخطوط الخارجية. لحفظ PDF اختر ذلك يدويًا من نافذة الطباعة؛ إغلاق النافذة لا يعني حفظ ملف، ويمكن فتح HTML في متصفح آخر عند تعذر الطباعة.

المسار `GET /api/applications/:id/report` للباحث صاحب الطلب فقط، مع `no-store`. يجمع الحالة والنسخة والسجل والإعلان من قراءة واحدة لوثيقة الطلب، دون تعديلها أو إنشاء ملف على الخادم، ولا يكشف هوية الموظف. تُفحص الجلسة وتطابق بيانات الطلب قبل عرضها. تُرفض البيانات الأكبر من 1MiB عند تجهيز النسخة بدل إنتاج ملف ناقص؛ الحد يطبق قبل اختيار الأقسام.

هذه نسخة للمراجعة تعكس البيانات المحمّلة وقت إعدادها، وليست إثباتًا موقّعًا أو تحديثًا مباشرًا. في الطلبات القديمة يُوضح غياب الإعلان المحفوظ أو السجل السابق؛ لا يُستبدل الإعلان القديم بوصف الوظيفة الحالي. قد تأتي أسماء الوظيفة والشركة من بياناتهما الحالية عند غياب النسخة المحفوظة، ويُذكر ذلك صراحة. يحتفظ السجل بحدّه السابق: آخر 100 حدث مع توضيح النقص. النسخة المحفوظة تبقى قابلة للقراءة بعد حذف الوظيفة، بينما سحب الطلب يحذف بياناته من المنصة ولا يحذف الملفات التي نزّلها صاحبه.

### حفظ السيرة وصندوق الرسائل

من `/cv` يستطيع المستخدم المسجل الضغط على «حفظ في حسابي» لحفظ كل حقول المحرر، بما فيها المشاريع والشهادات والقالب واللون. تُسترجع البيانات عند فتح الصفحة مجددًا. الحفظ يدوي؛ احفظ قبل مغادرة المحرر. يتاح للزائر إنشاء وتصدير سيرة في الذاكرة، دون حفظ حسابي أو نقل تلقائي للبيانات عند تسجيل الدخول.

يحفظ API بيانات المحرر في `builder_data` ضمن السيرة الخاصة بالمستخدم، مع إبقاء التوافق مع صيغة السيرة القديمة. يرسل المحرر `expected_updated_at` لمنع الكتابة فوق نسخة أحدث من نافذة أخرى، ويتيح استرجاع المحفوظ عند التعارض. اختبارات المحرر تشمل تحويل البيانات القديمة وعرض المشاريع والشهادات في القوالب العشرة.

تعرض `/admin/messages` رسائل الشركة مع صفحات وتصفية حسب القراءة وتعليم الرسائل كمقروءة. يشاهد مسؤول الشركة رسائل شركته فقط، ويمكن للمدير اختيار الشركة. زر الرد يفتح تطبيق البريد؛ لا يرسل الموقع ردًا تلقائيًا. تتوفر الروابط من لوحة الشركة والشريط الجانبي ودليل `/pages`.

### الملف الشخصي وأمان الحساب

من `/profile` يستطيع المستخدم تعديل الاسم والهاتف ورابط الصورة والبيانات الشخصية والأكاديمية والمهنية ولغات البرمجة. الحفظ يدوي، وتبقى الحقول الاختيارية قابلة للإفراغ. البريد الإلكتروني والدور والنقاط ليست قابلة للتعديل من هذا المسار. التعديلات الجزئية في API تحافظ على بقية حقول الاستبيان، ويُزامن الاسم مع `onboardingData.fullName` والصورة مع `avatar_url`.

تتيح الصفحة للحساب المحلي تغيير كلمة المرور بعد إدخال الحالية وتأكيد الجديدة. الحد الأدنى 8 أحرف والحد الأقصى 72 بايت UTF-8، مع منع إعادة استخدام الحالية ومحاولات التغيير المتكررة. تُدار كلمات مرور حسابات OAuth لدى المزود.

يُعيد `/api/auth/change-password` رمز جلسة جديدًا للمستخدم الحالي؛ تُبطل جميع الرموز ورموز التحقق الصادرة قبل التغيير. يتغير `token_version` ذريًا لمنع تغييرات متزامنة تستعمل كلمة المرور القديمة. الحسابات والرموز القديمة التي ليس لها إصدار تعمل كالإصدار صفر حتى أول تغيير، ولا تُرسل قيمة الإصدار في بيانات الملف. الاختبارات تستخدم حسابات وقواعد مؤقتة وبريدًا وهميًا، دون تغيير كلمة مرور حساب المعاينة الحقيقي.

### استعادة كلمة المرور المنسية

رابط «نسيت كلمة المرور؟» في `/login` يفتح `/forgot-password`. بعد طلب الاستعادة، يفتح `/reset-password` لإدخال البريد ورمز من 6 أرقام وكلمة جديدة مع تأكيدها، في المتصفح الذي طلب الرمز. تعمل الاستعادة للحساب المحلي النشط فقط؛ حسابات OAuth تستعمل مزودها.

يرسل الخادم رد استلام موحدًا للحساب الموجود وغير الموجود وOAuth والمعطل، ثم يحاول إرسال البريد للحساب المؤهل. لا يؤكد رد الاستلام وصول الرسالة. غياب إعداد البريد يعيد 503 للجميع، وتعرض الواجهة رسالة واضحة. عند فشل التسليم بعد المحاولات يُبطل طلب الاستعادة مع بقاء مهلة الطلب. الإرسال يجري داخل عملية الخادم بعد الرد؛ لا توجد قائمة بريد دائمة، لذلك قد يلزم طلب رمز جديد بعد انقطاع الخادم.

يُحفظ طلب مستقل في `PasswordResetChallenge` دون بريد صريح أو رمز صريح، مع HMAC للرمز وبصمة لسر المتصفح المحفوظ في cookie موقعة وHttpOnly وSameSite=Lax وSecure في الإنتاج. الصلاحية 10 دقائق و5 محاولات للرمز، و60 ثانية بين الطلبات للبريد نفسه حتى إذا لم يكن مسجلًا. يوجد حد 10 طلبات استعادة و30 محاولة تعيين لكل IP خلال ربع ساعة، فوق محددات المصادقة الموجودة. تنظيف TTL لا يحل محل فحص الصلاحية في الطلب نفسه.

طلب رمز جديد يلغي السابق، ولا يُقبل رمز الاستعادة لتسجيل الدخول. عند نجاح التعيين تُستهلك العملية مرة واحدة ذريًا، ويتغير إصدار جلسات الحساب، فتُبطل الجلسات ورموز الدخول والاستعادة الأقدم. يلزم تسجيل الدخول بالكلمة الجديدة ثم رمز بريد جديد. لا يوجد تجاوز للبريد أو تعيين تلقائي لكلمة مرور حساب المعاينة. الاختبارات تستخدم قواعد ومستخدمين مؤقتين وبريدًا وهميًا فقط.

### إدارة الحسابات والفريق

- `/admin/contacts` يعرض جميع الحسابات ببحث وفلاتر وصفحات من الخادم؛ `/admin/team` يعرض المديرين فقط. اختيار الحالة أو الصلاحية لا يحفظها قبل المراجعة والتأكيد.
- الحساب الحالي وحسابات المديرين محمية من تغيير الحالة والصلاحية في هذه الواجهة. صلاحية حساب الشركة وربطه تُدار من مسار الشركات. ترقية الباحث عن عمل غير المرتبط تحتاج بريدًا مؤكدًا وحالة مفعّلة.
- `GET /api/admin/users` يقبل `scope=all|staff` والبحث والصلاحية والحالة وتأكيد البريد والترتيب والصفحة، ويعيد ملخصات إدارية محدودة و`revision` لكل حساب. `PATCH /api/admin/users/:id/access` يستقبل `expected_revision` والحالة أو الصلاحية المطلوبة، ويزيد نسخة الإدارة ونسخة الجلسات ذريًا. كل تغيير ناجح يبطل الجلسات السابقة.
- مسارا `toggle` و`role` القديمان، وكذلك `DELETE /api/admin/users/:id`، يتطلبان الآن `expected_revision`. مسار `toggle` يحتاج `is_active` الصريحة ولا يقلب الحالة تلقائيًا. `DELETE` يوقف الحساب مع حفظ سجلاته بدل حذفها. الرد `409` يعني ضرورة إعادة القراءة قبل أي حفظ جديد.
- قوائم `/api/management/team` و`contacts` القديمة متاحة للتوافق بحد 100 ملخص؛ الواجهتان الجديدتان تستخدمان مسار الحسابات بصفحات ولا تعتمدان على هذا الحد. `team` القديم يعرض المديرين فقط أيضًا.

### التقويم الإداري

`/admin/calendar` ينظم أنشطة يوم كامل مشتركة بين المديرين، دون إرسال دعوات أو تنبيهات. يدعم البحث داخل الشهر، واختيار اليوم، وإضافة النشاط وتعديله وأرشفته واسترجاعه. الهاتف يستخدم حقل تاريخ واضحًا؛ وتظهر شبكة الشهر على المساحات الأوسع. تاريخ النشاط يوم مدني ثابت، وزر «اليوم» يعتمد Asia/Hebron.

المسار `GET /api/management/events/list` يتطلب `month=YYYY-MM` و`date=YYYY-MM-DD` ضمنه، مع البحث والحالة والصفحة. يعيد إحصاءات أيام الشهر وقائمة اليوم بصفحات، فلا يعتمد على حد 500 للقائمة القديمة. كل تعديل PUT أو أرشفة/استرجاع PATCH يحتاج `expected_version` من أحدث قراءة، ويزيد النسخة ذريًا. مسار DELETE القديم أصبح أرشفة قابلة للاسترجاع ويتطلب النسخة أيضًا؛ الطلبات القديمة دون نسخة تحصل على 400. قائمة GET القديمة تبقى مصفوفة لا تتضمن المؤرشفة، وبحد 500 للتوافق فقط.

إضافة النشاط تدعم `request_id` اختيارية من نوع UUID v4، وترسلها الواجهة دائمًا. يتقيد المفتاح بالمدير والبيانات الأصلية: تكرار نفس الطلب يعيد أحدث السجل دون إنشاء آخر، ولو أُرشف أو عُدّل؛ استعمال المفتاح ببيانات مختلفة يعيد 409. المفاتيح داخلية لا تظهر في قوائم الأنشطة. الأنشطة المشتركة مرئية للمديرين فقط؛ ليست تقويمًا شخصيًا ولا حجز مقابلات أو ساعات زمنية.

### المساعد الذكي

`/ai` يتحقق من توفر الخدمة عبر `GET /api/ai/status` دون استدعاء المزوّد. يحتاج الخادم إعداد `GROQ_API_KEY` و`GROQ_MODEL` لتفعيل الإرسال؛ لم تُضف هذه الخطوة مفاتيح ولم تستدعِ الخدمة الفعلية. حالة status تعني وجود الإعدادات وليست فحصًا حيًا لصلاحية المفتاح أو رصيد الخدمة.

المحادثة مؤقتة في الصفحة، ولا تُحفظ في الحساب أو تخزين المتصفح. الإرسال يحتاج موافقة ظاهرة على إرسال السؤال والسياق إلى Groq. لا يُقرأ الملف الشخصي أو CV تلقائيًا. الاقتراحات تملأ المسودة فقط، والفشل يبقي السؤال، والإيقاف يلغي انتظار الرد ويرسل إشارة إلغاء إلى المزوّد؛ لا يضمن ذلك إلغاء معالجة أو تكلفة سبق أن بدأت لديه.

عقد `POST /api/ai/chat` الحالي: `message` حتى 4000 حرف، و`request_id` من نوع UUID v4، و`allow_external_processing: true` إلزامية، و`include_jobs` اختيارية، و`history` حتى ثلاثة أزواج مكتملة user ثم assistant، بحد 12000 حرف للسياق. الحقول القديمة مثل `jobsList` مرفوضة، فيلزم تحديث المستهلكين القدامى. معرّف الطلب لتأكيد تطابق الرد فقط؛ لا يُنشئ ذاكرة منع تكرار أو ضمان فوترة مرة واحدة. لا توجد إعادة إرسال تلقائية.

إرفاق الوظائف اختياري وغير محدد افتراضيًا: الخادم يختار أحدث 10 وظائف مفعّلة، لم ينتهِ تقديمها، لشركات مفعّلة، ويرسل ملخصات عامة دون الرواتب أو الوصف أو بيانات الحسابات والتواصل. تظهر روابطها مستقلة عن النص المولّد؛ فتح صفحة الوظيفة هو مرجع التحقق من حالتها الحالية. لا يُدّعى أن هذه عينة شاملة لكل الوظائف.

الطلبات العامة لا تحمل رمز الدخول أو كوكيز عبر عميل المساعد. تبقى حماية تبديل الحساب محلية لمنع ظهور رد سابق بعد تغيّر الجلسة. الواجهة تعرض الرد نصًا دون HTML أو تنفيذ تعليمات، ولا توفر للمزوّد أدوات إرسال أو تعديل أو تشغيل أكواد. مزوّد Groq يعالج البيانات وفق سياساته خارج تحكم التطبيق؛ تعليمات تقليل الاختلاق لا تضمن صحة كل إجابة.

### ساحة التدريب ومحرر الأكواد

- `/practice` يعرض خمس تدريبات تمهيدية أصلية للقراءة من المصدر، ثم فهرس مسائل قاعدة البيانات ببحث حرفي ونوع وصعوبة وصفحات. `/practice/:id` يعرض السؤال أو بيان المسألة ورابط مصدر آمن. `/playground` محرر تجربة الأكواد، و`?problem=:id` يحتفظ بنص التدريب ورابط العودة إليه.
- التدريبات التمهيدية لا تُستورد إلى قاعدة البيانات. تصحيح السؤال عبر `POST /api/problems/:id/check` يحتاج تسجيل الدخول و`answer_index` فقط، ويعيد شرحًا دون حفظ محاولة أو منح نقاط أو تقييم توظيف. مفاتيح الإجابات والشرح لا تظهر في القراءة العامة أو خطط الدراسة قبل التصحيح. الإجابات المخزنة يدعمها التصحيح عند تطابق نص خيار أو حرف A..Z؛ السؤال غير المكتمل يعيد 422.
- قوائم `/api/problems` الحالية محدودة حتى 50 سجلًا في الطلب، والواجهة تستخدم 12. الرد يحافظ على أسماء `data/currentPage/totalPages` ويعيد ملخصات بدل مستندات كاملة. لا تعتمد واجهة على نسب نجاح أو أعداد محاولات افتراضية.

محرر الكود يحتفظ بمسودة مستقلة لكل لغة في ذاكرة الصفحة فقط، ولا ينفذ النص داخل المتصفح أو عملية API. التشغيل الفعلي يحتاج خدمة معزولة متوافقة مع عقد Piston مضبوطة لدى المالك في `CODE_EXECUTOR_URL`، ورمز bearer اختياري في `CODE_EXECUTOR_TOKEN`. فُعّلت خدمة محلية على جهاز التطوير؛ تفاصيلها وإعادة تشغيلها في `executor/README.md` وفي فقرة إعداد التنفيذ أدناه. يلزم تثبيت اللغات وضبط حدود العزل والموارد لدى أي خدمة جديدة واختبار توافقها؛ وجود الإعداد ليس فحصًا حيًا لصلاحيتها. عنوان التنفيذ يتطلب HTTPS، عدا localhost في التطوير، ولا تُتبع التحويلات. لا يفترض التطبيق توفر واجهة Piston عامة مجانية. راجع [توثيق Piston الرسمي](https://github.com/engineer-man/piston/blob/master/readme.md) لعقد التنفيذ ومتطلبات التشغيل والمزوّد.

`GET /api/submissions/status` عام ويقرأ اللغات المثبتة فعليًا من خدمة التنفيذ دون تشغيل كود. يعيد `configured/available/host/languages/installed_languages/state/checked_at` وحدود النص؛ اسم المضيف فقط دون URL الكامل أو رمزه. `configured` يعني وجود إعداد صالح، و`available` توفر لغة مدعومة واحدة على الأقل؛ `ready` للخمس و`partial` لبعضها. الواجهة تتيح كتابة وتنزيل مسودة كل لغة، وتمنع تشغيل اللغة الغائبة. يجب تحديث مستهلكي عقد status القديم إلى الحقول الجديدة.

فحص الجاهزية يطلب `/runtimes` الشقيق لمسار قياسي ينتهي بـ`/execute` من نفس الأصل، دون query أو hash أو تحويلات. مهلة الفحص ثلاث ثوانٍ وحجم الرد حتى 128 KiB، مع مشاركة الطلبات المتزامنة وتخزين نتيجتها خمس ثوانٍ داخل عملية API. لا تُرسل جلسة المستخدم؛ يُستخدم رمز المالك الاختياري فقط. المسارات المخصصة غير القابلة للتحقق تظهر `unverifiable` وتمنع التنفيذ. يبقى المضيف والإعداد ظاهرين عند انقطاع الخدمة. وقت الفحص لقطة للحالة، وليس ضمانًا لاستمرار الاتصال أو اختبارًا لأمان العزل.

`POST /api/submissions/run` يحتاج تسجيل الدخول و`request_id` UUID v4 و`allow_external_processing:true` والكود حتى 50000 حرف، وstdin حتى 8000 حرف، ولغة من JavaScript/Python/Java/C/C++. يفحص الخادم اللغات مجددًا قبل كل إرسال، دون الاعتماد على النتيجة المخزنة، ويعيد 503 عند عدم توفر الخدمة أو اللغة. قد يفشل التنفيذ بعد نجاح الفحص بسبب تغير الخدمة. لا يُعاد إرسال الكود تلقائيًا. يرسل الخادم ملفًا واحدًا ثابت الاسم ونسخة runtime `*`، وحدودًا ثابتة للترجمة والتشغيل والذاكرة. هذه حدود طلبات إلى الخدمة وليست إثباتًا أن خدمة غير مهيأة أو غير متوافقة تطبقها.

تقتصر الطلبات على 10 محاولات لكل IP في الدقيقة، وتشغيل واحد معلق لكل حساب داخل عملية API. الإلغاء يقطع انتظار المتصفح ويرسل إشارة إلى الخدمة، دون ضمان إلغاء معالجة أو تكلفة بدأت لديها. request_id لتطابق الرد فقط، وليس مفتاح منع تكرار دائم. لا إعادة إرسال تلقائية.

حالة `completed` تعني انتهاء البرنامج بنجاح فقط؛ لا تستخدم `Accepted` ولا تمنح حكمًا بصحة حل المسألة أو نقاطًا. تُفصل أخطاء الترجمة والتشغيل والوقت وحد المخرجات، وتُرفض النتائج المشوّهة، وتُحدّ النصوص بـ20000 حرف لكل حقل مع إشارة اختصار. لا تُحفظ الكودات أو المحاولات في قاعدة البيانات. مستهلكو `/run` القديم يحتاجون العقد الجديد، وقراءة `data.state/phase` بدل حالة Accepted القديمة.

بعد استلام نتيجة يظهر قسم «قارن بالمخرج الذي تتوقعه». يقارن `stdout` فقط بنص اختياري يكتبه المستخدم حتى 20000 حرف، محليًا دون إرسال أو تخزين. يُسمح بالنص الفارغ بعد ضغط المقارنة صراحةً. تُوحّد CRLF إلى LF دائمًا، ويوجد خيار مفعّل افتراضيًا لإزالة LF واحدة من نهاية كل نص؛ بقية المسافات وعلامات Tab وحالة الأحرف والأسطر مؤثرة. يظهر أول اختلاف بالسطر والحرف مع تمييز المسافة وTab والسطر ونهاية النص. تُحسب المواضع بنقاط Unicode وTab حرفًا واحدًا، وليست أعمدة العرض المرئية. لا تُجرى مطابقة Unicode أو أرقام تقريبية أو تصحيح مسألة أو نقاط. تُمنع المقارنة أثناء الانتظار أو عند تغير الكود/الإدخال/اللغة عن النتيجة أو فشل التشغيل أو اختصار مخرجاته. لكل نتيجة جديدة حقل متوقع جديد، ولا يُضمّن النص المتوقع في ملفات المسودات أو تنبيه مغادرتها. العرض الرئيسي للمخرجات يبيّن stdout وحده، وتبقى stderr منفصلة.

### حفظ السيرة الذاتية ومعاينتها

`/cv` يتيح تجربة القوالب وتصدير نسخة محلية للزائر، وحفظًا يدويًا للسيرة في الحساب المسجّل. لا تنتقل مسودة الزائر تلقائيًا عند تسجيل الدخول. يقرأ العميل نسخة المستخدم ومعرفها ووقت تحديثها، ويربط كل قراءة وحفظ بجلسة الحساب الأصلية، بطلبات خاصة `no-store` ودون إرسال cookies. يرفض الرد غير المقروء أو هوية/نسخة غير صالحة، ولا يعلن الحفظ دون `success:true` ومعرف السيرة المطابق ووقت تحديث صالح. يتحقق من أنواع حقول المحرر وحدودها وحجم الطلب (1 MiB بترميز UTF-8) قبل الإرسال؛ تحقق الخادم هو المرجع النهائي.

عند تعديل السيرة أثناء انتظار الحفظ تبقى التعديلات اللاحقة غير محفوظة حتى تُحفظ بنفسها. تعارض النسخ 409 يبقي المسودة ويمنع تكرار الحفظ حتى استرجاع النسخة الأحدث بعد تأكيد صريح. إلغاء الاسترجاع أو فشله يحتفظ بالتعديلات الحالية، ولا يسمح فشل القراءة الأولى بتحرير نسخة بديلة قد تطغى على المحفوظ. لا إعادة حفظ تلقائية بعد فشل الشبكة أو الرد غير المؤكد؛ يمكن مراجعة المحفوظ للتحقق مما وصل للخادم.

توجد حماية للمغادرة إلى مسار آخر داخل الموقع عند وجود تعديلات أو حفظ قيد الانتظار، وتنبيه تحديث/إغلاق يعتمد على دعم المتصفح. تغيير الحساب أو تعطل المتصفح لا يضمن استرجاع المسودة. لا حفظ دائم لمسودة الزائر أو نسخة محلية تلقائية. إلغاء انتظار الحفظ عند المغادرة لا يضمن إلغاء كتابة بدأت على الخادم.

على الشاشات الصغيرة تظهر المعاينة في خطوة «المعاينة والتحميل»، مع تمرير داخل إطارها بدل تمديد الصفحة. أصبح تصدير PDF وWord بتنسيق A4 موحّد مستقل عن القوالب المرئية، مع جميع الأقسام النصية وروابط المشاريع والشهادات والتقنيات وتفاصيل التعليم. تظهر نسخة التصدير للمراجعة قبل الطباعة، ثم يفتح زر PDF نافذة الطباعة للحفظ؛ لا يُعلن أن الإلغاء أو فتح النافذة يعني اكتمال حفظ ملف. يبقى إطار المعاينة حتى يغلقه المستخدم، وتنتظر الطباعة جاهزية الخطوط بدل مهلة ثابتة وحذف الإطار سريعًا.

Word ملف `.docx` حقيقي يُولّد محليًا بمكتبة `docx` المثبتة بالإصدار 9.15.3، وتُحمّل حزمته عند طلب Word فقط. يستعمل نفس ترتيب المحتوى النصي للتصدير، واتجاهًا مستقلًا لكل فقرة مع اتجاه ثابت للروابط وأرقام الاتصال. لا يُرسل محتوى السيرة لخدمة خارجية، ولا يُضاف ربط خارجي أو تنزيل صور؛ الروابط نصوص قابلة للقراءة. يُرفض النص غير الصالح لـXML والحجم المفرط، وتُنظف أسماء ملفات التنزيل. نجاح طلب التنزيل ليس إثبات اكتمال الملف على القرص.

فُحصت أمثلة عربية طويلة وإنجليزية قصيرة فعلية من مولدي التطبيق: DOCX عبر LibreOffice المحلي، وPDF من نفس HTML للطباعة عبر Edge headless. روجعت صفحاتها المرئية ونصوصها وقياس A4 ووجود آخر قسم؛ الأمثلة مصطنعة وليست سير أشخاص حقيقيين. لا يضمن ذلك التطابق في كل إصدار Word أو كل متصفح أو طابعة. لم يُستكمل حفظ PDF يدويًا من نافذة المتصفح المضمّن، ولا اختبار Microsoft Word نفسه. لا ضمان توافق ATS أو نتيجة توظيف.

### بيانات التدريب من فرع NadaNour

مصدر الملفين في `data/` هو `ZEE582/cv1`، فرع `NadaNour`، عند commit `566fdf547f5e691c5c27250d4100f2202500816f`. وُثقت روابط النسخة المثبتة وبصمات Git blob وSHA-256 في `data/source-manifest.json`. لم يُدمج كود الفرع القديم؛ ملفا JSON مطابقان للموجود سابقًا في هذه النسخة.

الملفان يحتويان 2676 مسألة برمجية و137 سؤالًا. `LC-37` مكرر مرتين بنفس المحتوى؛ أداة الاستيراد تتجاوز النسخة المطابقة، فيصبح العدد 2812 سجلًا فريدًا: 2675 مسألة و137 سؤالًا. جميع مفاتيح الأسئلة الـ137 تطابق خيارًا محفوظًا أو ترميز A..Z. المسائل البرمجية تتضمن عنوانًا وتصنيفًا ورابطًا إلى مصدرها؛ لا يعني استيرادها توفر بيان كامل أو اختبارات تحكيم آلية.

من جذر المشروع، وبعد ضبط `MONGO_URI` لقاعدة التطوير المقصودة:

```sh
npm run import:practice -w backend -- --dry-run
npm run import:practice -w backend -- --apply
```

الافتراضي قراءة وخطة فقط. `--apply` يضيف السجلات الناقصة دون تعديل الموجودة أو أعداد محاولاتها ونقاطها. يرفض البيانات غير الصالحة وتعارض المعرّفات قبل أي كتابة، ويستعمل دفعات و`$setOnInsert` دون لمس الطوابع الزمنية للسجلات الموجودة. يعيد الاستيراد بعد فشل جزئي بأمان بإضافة الناقص؛ لا يوفر معاملة ذرية تشمل كل الدفعات. تطبيق الاستيراد في `NODE_ENV=production` معطل ويحتاج مسار ترحيل معتمدًا. السكربت قابل للاستدعاء كمكتبة دون اتصال أو استيراد تلقائي لمجرد require.

استُوردت السجلات الـ2812 إلى قاعدة التطوير المحلية الجارية يوم 5 نوفمبر 2026، وتظهر في `/practice`، وتصفية نوع «أسئلة» تعرض 137 سؤالًا. بقية السجلات والحسابات والتدريبات الخمسة الثابتة لم تتغير. إعادة الأمر تحافظ على الموجود؛ ليست أداة لمزامنة التعديلات أو الحذف من الملفات إلى قاعدة بيانات سبق تعديلها.

### التنقل وأمثلة قراءة الإدخال

تحمل روابط المسائل والمحرر فلاتر الفهرس والبحث ورقم الصفحة في `from`، ويعيد زر «العودة إلى نتائج التدريب» إلى القائمة نفسها حتى بعد نسخ الرابط أو تحديث الصفحة. الوجهة مقصورة على `/practice` ومعاملاته المدعومة؛ تُحذف المعاملات الأخرى ولا يُقبل عنوان خارجي أو مسار صفحة أخرى. يظهر رابط المصدر أيضًا داخل نص التدريب القابل للتوسيع في المحرر.

يوفر المحرر مثال رسالة ترحيب ومثال قراءة عددين من stdin وجمعهما لكل من JavaScript وPython وJava وC وC++. تحميل المثال يتطلب تأكيد استبدال كود اللغة الحالية وإدخالها؛ الإلغاء يبقي المسودة، وتبقى مسودات اللغات الأخرى. مثال الإدخال يضع `2 3` ويشرح أن `5` مخرجه المتوقع، دون عرضه كنتيجة تشغيل أو حل تلقائي للمسألة المرتبطة. لا يحفظ هذا التحديث المسودات بعد مغادرة المحرر أو إعادة تحميل الصفحة، ولا يفعّل خدمة التنفيذ غير المهيأة.

### إعداد خدمة التنفيذ وفحصها

إعداد Piston المحلي الاختياري في [executor/README.md](executor/README.md)، مع صورة رسمية مثبتة ببصمة GHCR وملف Compose منفصل يفتح loopback فقط. يحتاج طريقة التشغيل الرسمية إلى حاوية `privileged`؛ راجع أثر هذه الصلاحية على مضيف Linux أو آلة Docker الافتراضية قبل تشغيلها. لا يشغّل المشروع الحاوية أو يثبت Docker أو اللغات تلقائيًا. يوجد سكربت تهيئة Ubuntu مستقل ومحروس بمتغير صريح، لا يستدعيه `npm run setup`.

`npm run check:executor` يفحص إعداد المالك واتصال `/runtimes` واللغات الخمس دون تشغيل كود، ويخرج بالرمز 2 عند عدم الجاهزية. `npm run check:executor -- --smoke` يطلب صراحةً تجربة خمسة برامج ثابتة لجمع 2 و3 ويتحقق من stdout الفعلي. لا يقرأ كود مستخدم أو حسابه، ولا يطبع عنوان الخدمة الكامل أو رمزها. الفحص التشخيصي ليس حكمًا على أمان العزل أو بديلًا لفحص المضيف؛ توفر لغات المحرر يحتاج تثبيتها لدى الخدمة.

فُعّل التنفيذ المحلي يوم 5 نوفمبر 2026 بعد موافقة المالك: Docker Engine 29.9.3 داخل Ubuntu 24.04 WSL، وصورة Piston المثبتة بالبصمة، وحزم JavaScript 20.11.1 وPython 3.12.0 وJava 15.0.2 وC/C++ 10.2.0. نجحت أمثلة اللغات الخمس فعليًا، وأظهر زر التشغيل في المنصة الناتج 5 للإدخال 2 و3، ونجح فحص المهلة وحد المخرجات. أُعد عنوان الخدمة في `backend/.env` المحلي فقط، دون تضمين الأسرار أو Docker أو حزم اللغات في ZIP. إعادة تشغيل الخدمة وتجهيز جهاز آخر موضحان في `executor/README.md`؛ الموقع لا يثبت أو يبدأ حاوية privileged تلقائيًا.

### النسخ الاحتياطي لقاعدة المنصة

أُضيفت أوامر `backup:init` و`backup:create` و`backup:verify` لنسخ MongoDB 7 مشفرًا والتحقق بالاستعادة على قاعدة مؤقتة منفصلة. تشمل مرفقات السير، وتبقى النسخ والمفتاح خارج Git وZIP. أوقف الكتابات قبل النسخ واحفظ المفتاح بصورة منفصلة محمية؛ فقدانه يمنع الاسترجاع. خطوات التجهيز والقيود في [دليل النسخ الاحتياطي](docs/database-backup.md). لا توجد استعادة تلقائية فوق قاعدة المنصة أو نسخ خارج الجهاز.

### حماية المسودات وتنزيلها

يمكن تنزيل كود اللغة الحالية باسم ثابت مناسب لها (`main.js` أو `main.py` أو `Main.java` أو `main.c` أو `main.cpp`)، وتنزيل stdin في `input.txt`، أو تنزيل ملف `ttwar-drafts.json` يجمع مسودات اللغات الموجودة والإدخال وسياق المسألة. يحافظ التنزيل على النص والمسافات، ولا يرسل الكود إلى API أو يضيف رمز الحساب أو بياناته إلى الملف. يمكن استرجاع نسخة JSON داخل المحرر وفق الخطوة التالية.

عند وجود تعديل في أي لغة أو في stdin، أو تشغيل قيد الانتظار، يظهر تأكيد قبل مغادرة المحرر عبر الروابط أو القائمة أو زر الرجوع. يمكن البقاء أو تنزيل جميع المسودات ثم تأكيد المغادرة. يبدأ السياق الجديد بمسودات جديدة عند الانتقال إلى مسألة أخرى؛ تبقى تغييرات فلاتر الرجوع وحدها ضمن السياق نفسه. نُقلت تهيئة التطبيق إلى `createBrowserRouter` و`RouterProvider` لدعم `useBlocker` الرسمي، مع إبقاء تعريفات الصفحات والصلاحيات الحالية.

التنزيل يطلب حفظ ملف من المتصفح ولا يثبت اكتمال حفظه على القرص؛ لذلك يبقى تنبيه المغادرة حتى التأكيد الصريح. أُضيف `beforeunload` للتحديث أو إغلاق الصفحة عند وجود عمل مؤقت، لكن ظهور التنبيه يعتمد على المتصفح ولا يضمن الحماية من تعطل التطبيق أو إغلاقه قسرًا أو تبديل الحساب. لا يوجد حفظ تلقائي في الحساب أو localStorage للمسودات، وتظل ذاكرة المحرر مؤقتة بعد المغادرة المؤكدة.

### استرجاع نسخة المسودات

من «استرجاع نسخة محفوظة» اختر ملف JSON نزّلته من المحرر. يُقرأ محليًا بترميز UTF-8، حتى 2 ميغابايت؛ لا يُرفع إلى API ولا يُنفذ محتواه. يُتحقق من format/version=1 والحقول واللغات الخمس وحدود 50000 حرف للكود و8000 للإدخال، وتُرفض الحقول واللغات غير المعروفة أو الملف غير المكتمل دون تطبيق جزئي. تقبل النسخ UTF-8 مع BOM، وتبقى المسافات والأسطر والنصوص الفارغة كما هي.

تعرض نافذة التأكيد اسم الملف واللغات وأحجام النصوص واللغة النشطة ومعاينة نصية محدودة للكود، ويمكن تنزيل نسخة من العمل الحالي أو الإلغاء. التأكيد يستبدل مسودات اللغات الموجودة في الملف فقط ويحافظ على بقية اللغات، ويعيد اللغة النشطة المحفوظة. يبقى التدريب المفتوح كما هو؛ معرف المسألة في الملف مرجع فقط ولا يسبب تنقلًا تلقائيًا، ويظهر اختلافه بوضوح.

عند الاسترجاع تُمسح نتيجة التشغيل القديمة وتُلغى الموافقة السابقة على إرسال الكود؛ لا تشغيل تلقائي ولا حفظ في الحساب أو نقاط. قراءة قديمة انتهت بعد مغادرة الصفحة أو تبديل الحساب لا تُطبَّق، ويمكن إعادة اختيار الملف نفسه بعد الإلغاء أو الفشل. يبقى منع فقدان المسودات أثناء التنقل فعالًا بعد استرجاعها.
